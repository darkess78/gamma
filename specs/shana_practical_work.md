## Scope and authority

The existing coordinator owns practical activities, accepted decisions,
personal state and result communication. A worker receives an explicit finite
task specification, selected source files, an editable subset and protected
check modules. It cannot choose a host repository, a shell command, a provider,
an external submission or a production activation.

Research can inspect the selected task material and produce sourced notes and a
plan. Research does not grant build authority. Preparing a build task records a
ready candidate. Execution requires an explicit start or a previously authorized
start accepted through the private conversation contract. Interesting discussion
alone does not start implementation.

The practical worker uses the existing private journal, immutable artifact store,
per-run process lease and Linux sandbox. It does not introduce a second planner
or personal-state database. The original input scope, maximum attempts, absolute
deadline and consumed attempts survive pauses and owner replacement. An uncertain
inference request requires review instead of automatic replay.

The current task packet accepts up to 20 portable UTF-8 files with 60,000 bytes
of total source, an editable subset and up to six protected Python checks. A
build requires editable files and checks. Research permits neither. Each task
has one to five model attempts and a 30 to 1,800 second absolute budget. The
model context has a separate smaller limit and rejects oversized prompts before
inference. Standard-library module names, private configuration names, path
traversal, Windows device names and portable path collisions are rejected.
Protected check package initializers cannot be edited.

Candidate preparation and testing have no promotion path. New APIs are limited
to the isolated authenticated factories. Production factories, service units,
listeners, local configuration and installed source remain outside this change.

## Evidence and result meaning

Selected-source research, a proposed plan, an accepted candidate and checked
behavior have distinct evidence. Protected checks bind to the exact saved
candidate and contract. A generated test is insufficient for completion. The
acceptance journey must exercise each actual tool and its changed request.

Owner-supplied checks are trusted task requirements. Separate acceptance checks
exercise the actual command-line artifacts against inputs withheld from the
specialist. A successful public check receipt alone does not establish that
unfamiliar cases work. Source corruption after an earlier successful observation
must also invalidate a later explicit completion reply.

Progress and completion replies identify their activity and checked evidence.
Missing capability, exhausted attempts, expired authority, invalid evidence or
uncertain effects produce a specific blocker. They cannot be reported as a
successful practical result. Private source and task details remain unavailable
to shared or unbound audiences.

A specialist can return a bounded missing-input, missing-capability or scope
question with no edits. The coordinator binds that request to the current
source and contract, retains the consumed attempt and waits for the owner. It
does not retry, fabricate the missing input or grant the requested authority.
Any revised source or scope needs a new explicit finite task.

## Private interfaces

Only the isolated factories expose these authenticated routes. Every operation
also requires the explicit `owner_private` audience.

| Interface | Behavior |
| --- | --- |
| `POST /v1/coordination/work` | Prepare a finite source packet or explicitly start its exact task ID. Preparing alone does not execute it. |
| `GET /v1/coordination/work` | List practical activity metadata, or inspect one task's validated source, checkpoint and receipts. |
| `GET /v1/coordination/work/artifact` | Download the exact validated candidate and source hash as JSON. |
| `/api/coordination/work*` | Authenticated private dashboard proxies for those API routes. |
| `/dashboard/work` | Private confirmation, task preparation, start and candidate review. Clearing private confirmation clears its source display. |

Existing private activity controls pause, resume, switch and stop practical work
at safe checkpoints. Private dialogue can start the exact prepared task only
when its finite scope already permits a conversational start. A duplicate
request ID returns its original result; a changed payload with that ID is
rejected. The public conversation schema gains no practical-work authority.

The private runtime uses the selected local model under existing background
admission. Its specialist can inspect supplied source and documents and propose
edits or a plan. It cannot browse arbitrary websites, select paid providers or
run arbitrary host commands. These task limits remain visible in review rather
than being inferred away from successful examples.

Idle admission waits ranged from 0.142 to 1.004 milliseconds. The raw report
retains per-call model-load timings, which ranged from about 0.9 milliseconds
to 5.77 seconds. A dialogue can contain multiple model calls. Warm means the
model was resident before the task; the worker's existing unload policy can
make the later foreground request cold. The comparison preserves that policy
rather than claiming the later foreground conditions were identical.

This private path buffers its response, so the API returns its first text with
the full reply. The measurements record complete HTTP reply arrival. Browser
paint time, separate model first-token time and voice start were not measured.
Background work materially delayed conversation in these samples. This is a
known limitation for user review, not evidence of accepted everyday usability,
a latency guarantee or a percentile estimate.

Cancellation was measured after the reply at an explicitly held, durably saved
candidate boundary. Request acknowledgement took 54.848 to 62.086 milliseconds.
The stopped state was observed after 208.542 to 224.646 milliseconds with
100-millisecond polling. These are safe-boundary observations. They do not
measure preemption of an active generation. The timing gate did not replace
model choices, generated source or checks.
